# D0 — Documento de Definición del Problema  
**Sistema:** Aplicación web interna de ventas y control de stock  
**Negocio:** Minimarket "La Esquina" — Cañete  

---

## 1. Problema

El minimarket "La Esquina" no cuenta con un registro digital de ventas ni de stock, lo que impide conocer cuánto se vende al día y genera desabastecimiento de productos por falta de alertas oportunas.

---

## 2. Usuarios y Proceso Actual

| Elemento | Descripción |
|---|---|
| **Usuario del sistema** | Cajero del minimarket |
| **Proceso actual** | Las ventas se anotan manualmente en un cuaderno; el stock se revisa mirando los estantes físicamente |
| **Dificultad principal** | No se sabe cuánto se vendió en el día, no hay aviso cuando un producto está por agotarse y existe riesgo de quedarse sin mercadería |

---

## 3. Requisitos Funcionales (RF)

| ID | Nombre | Descripción |
|---|---|---|
| RF01 | Registrar producto | El cajero puede dar de alta un producto con su código, nombre,categoria,precio de venta, stock actual y stock mínimo |
| RF02 | Listar productos con alerta de stock | El sistema muestra la lista de productos y resalta visualmente aquellos cuyo stock actual está por debajo del mínimo definido |
| RF03 | Registrar venta con descuento de stock | El cajero registra una venta seleccionando productos y cantidades; el sistema descuenta automáticamente el stock y guarda el registro de la venta |
| RF04 | Listar ventas del día con total | El sistema muestra todas las ventas realizadas en la fecha actual junto con el monto total acumulado del día |

---

## 4. Requisitos No Funcionales (RNF)

| ID | Categoría | Descripción |
|---|---|---|
| RNF01 | **Integridad de datos** | El stock debe reflejar en todo momento el estado real del inventario; ninguna operación debe dejar el stock en un estado inconsistente |
| RNF02 | **Seguridad de datos** | La información de ventas y productos debe almacenarse de forma persistente y protegida contra pérdida o corrupción por fallos en la operación |

---

## 5. Reglas de Negocio (RN)

| ID | Regla |
|---|---|
| RN01 | La cantidad de productos en una venta debe ser mayor que cero (cantidad > 0) |
| RN02 | No se puede vender una cantidad mayor al stock disponible del producto |
| RN03 | El precio de un producto no puede ser negativo (precio ≥ 0) |
| RN04 | El código de cada producto debe ser único en el sistema; no se permiten duplicados |
| RN05 | El registro de la venta y el descuento del stock deben realizarse de forma atómica: si alguna parte falla, ninguna de las dos operaciones se aplica (todo o nada) |

---

## 6. Fuera de Alcance y Supuesto

### 6.1 Fuera de Alcance

- **Autenticación / login:** El sistema no contempla control de acceso por usuarios ni contraseñas.  
- **Gestión de clientes:** No se registran datos de clientes ni historial por cliente.  
- **Generación de boletas o comprobantes:** El sistema no emite ni imprime documentos tributarios.

### 6.2 Supuesto

> Se asume que la aplicación es usada **exclusivamente en la red interna del negocio** por el cajero, y que el dispositivo desde el que se accede es de uso dedicado al puesto de caja, por lo que no se requiere control de acceso para el alcance de este sistema.
